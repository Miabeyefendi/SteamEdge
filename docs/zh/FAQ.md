## 安全性與封鎖

### 我會被封鎖嗎？

沒有人能保證不會。以下是實際情況，讓你自行判斷。

**SteamEdge 做了什麼：** 它送出的 `ClientGamesPlayed` 訊息，與你啟動遊戲時官方 Steam 用戶端
送出的完全相同。Steam 看到有遊戲在執行，於是照常掉落卡牌。整個機制就是這樣。

**它沒有做什麼：** 不修改遊戲檔案、不注入任何處理程序、不使用 Steam Web API 金鑰、
不影響其他玩家、不代你交易或贈送，也完全不與受 VAC 保護的遊戲互動。

**誠實的風險：** 將帳戶自動化違反
[Steam 訂閱者協議](https://store.steampowered.com/subscriber_agreement/)。
這類工具已存在十多年，也未曾因farm卡牌出現大規模封鎖，但「沒發生過」不等於「不會發生」。
Valve 隨時可以改變政策。這個風險由你自行承擔。

### 會牽涉到 VAC 嗎？

不會。VAC 封鎖是針對在執行中的遊戲處理程序內作弊。SteamEdge 從不啟動遊戲，
因此沒有任何處理程序供 VAC 檢查。

### 真正讓人出事的是什麼？

不是farm卡牌本身，而是這些會引起注意的行為：

- **在數分鐘內解鎖數百個成就。** 這會公開顯示在你的個人檔案上，第三方網站也會追蹤。
  請使用安全模式與合理的間隔。
- **交易與市集濫用** - 這不是本應用程式會做的事，但把farm自動化的人往往也會自動化其他事。
- **分享 `settings/` 資料夾。** 該資料夾含有你的登入權杖，拿到它的人就等同於你。

### 我的密碼會被儲存嗎？

不會。使用 QR 登入時你完全不必輸入密碼；使用密碼登入時，密碼只用來取得一次權杖，之後即丟棄。
被儲存的是 Steam 核發的更新權杖，位於 `settings/session.json`。

請把 `settings/` 當作密碼看待：不要上傳、不要放進共用資料夾、不要附加在問題回報中。

## 常見問題排解

### Windows 顯示「Windows 已保護您的電腦」

執行檔沒有程式碼簽章。憑證每年要價數百美元，免費的業餘專案負擔不起。
請點選**其他資訊 → 仍要執行**，或[自行建置](./SETUP.md#自行建置)。

### 出現「SteamEdge 已開啟」然後應用程式關閉

同時只能執行一份。如果兩份一起跑，Steam 會中斷第一個工作階段（`LogonSessionReplaced`），
頁面就會顯示「未連線」。請關閉已開啟的視窗後重新啟動。

### 成就或庫存顯示「未連線」

Steam 工作階段被另一次登入接管。通常表示同一帳戶的 Steam 用戶端正開著，
或另一份 SteamEdge 正在執行。關閉另一個後按**重試**。

### 市集方塊顯示「Steam 請求限制」

Steam 每個帳戶約每 30 秒允許 20 次市集請求。SteamEdge 會將所有請求排入單一通道，
確保彼此不重疊，但若你快速連續開啟大量物品詳情，仍可能達到上限。

稍等一分鐘後按**重試**。若要避免，請先篩選再使用**取得價格**，而不是載入整個庫存。

### 價格看起來不對

價格以你 Steam 錢包本身的貨幣取得，讀自社群市集，並完全以該貨幣顯示，沒有任何換算。

若某個數字看起來不對，請確認你在看哪個方塊：

- **目前掛單**是賣家的開價，可能很離譜 - 有人可以把物品掛到 999,999 美元。
- **已成交販售**才是實際成交價，那才是真正的價值。

### 卡牌沒有掉落

依序檢查：

1. **該遊戲還有卡牌可掉嗎？** 按下重新整理遊戲清單。
2. **該遊戲超過 2 小時遊玩時數了嗎？** 在此之前 Steam 不會掉卡。快速模式會自動處理。
3. **帳戶符合資格嗎？** Steam 要求帳戶至少有一筆 5 美元消費，才能取得卡牌掉落。
4. **是否有其他 Steam 工作階段干擾？** 請關閉 Steam 用戶端。

### 應用程式佔用很多記憶體

這是 Electron 的特性：它以多個程序執行，所以工作管理員會顯示好幾列 SteamEdge。
設定 → 進階 → **已使用記憶體**會替你加總，並顯示各程序各佔多少。在我們的機器上，
一般使用情況總計約 200-240 MB。

有兩個方法可以降低用量：

- **關閉硬體加速**（設定 → 進階）。顯示卡程序會縮小；在我們的量測中總量從 212 MB
  降到 163 MB，代價是改由處理器繪製。
- **背景收集**（卡片收集 → 自動化）。視窗隱藏時，目前分頁的清單會從記憶體釋放，
  回到前景時重新繪製。

你沒有在看的分頁清單本來就會自動釋放，而且視窗隱藏時繪製會完全停止。

### 我要如何更新？

SteamEdge 只在啟動時檢查一次發佈清單，且僅在有新版本時顯示視窗；若已是最新版本則不會打擾你。
上方工具列的下載按鈕可隨時重新檢查。

程式永遠不會自行更新。請自行從發佈頁面下載新的壓縮檔，解壓縮到一個**全新且空白的資料夾**，
再把舊的 `settings/` 資料夾複製到新的 `SteamEdge.exe` 旁邊。你的設定、已儲存的帳號與登入狀態
都會一起帶過去。

唯一要避免的是把新版本解壓縮**覆蓋**在舊資料夾上：使用中的檔案會被略過，最後會混雜兩個版本的
檔案，程式將無法啟動。

### 我的檔案在哪裡？

在 `SteamEdge.exe` 旁邊的 `settings/` 與 `cache/` 中。
設定 → 進階 →**開啟資料夾**會帶你過去。

如果你把應用程式解壓縮到 `C:\Program Files`，Windows 會阻擋寫入，應用程式會改用 AppData 資料夾。
把資料夾移到可寫入的位置即可恢復可攜式配置。

## 功能

### 我可以同時執行多個帳戶嗎？

可以。頭像選單 →**新增帳戶**。所有已登入的帳戶都會在背景平行farm；視窗顯示你切換到的那一個。

### 時數提升真的有效嗎？

有效 - Steam 會為每個同時開啟的遊戲計算遊玩時數，已知上限為 32。
該上限由 Steam 伺服器執行，而非本應用程式。

### 什麼是時數同步？

它會分階段把多款遊戲的總時數拉齊到同一數字。見[教學](./TUTORIAL.md#時數同步)。

### 我可以把成就重新鎖定嗎？

可以，但原本的解鎖日期會永久遺失。

### 沒有 Steam 手機應用程式也能用嗎？

可以，但你必須手動輸入 Steam Guard 驗證碼，而批次市集上架也需依你的帳戶設定逐一確認。

### Linux / macOS？

目前僅建置 Windows 版本。程式碼是純 Electron，沒有 Windows 專屬相依項，
因此 `npm run build -- --platform=linux` 很可能可以產生可用版本，但未經測試也不提供支援。

## 專案

### 這是 Idle Master / ASF 的分支嗎？

不是。它是從零開始撰寫的。那些專案是為了理解 Steam 的運作方式而研究，並未複製任何程式碼。
完整致謝見 [README](./README.md#致謝)。

### 為什麼採用 AGPL-3.0？

為了讓任何再散布它、或將修改版本作為服務執行的人，都必須保持原始碼開放。
若你想用於封閉產品，請聯絡作者洽談商業授權。

### 我要如何回報問題？

開立 issue 並提供：

1. 你做了什麼、預期什麼、實際發生什麼。
2. 你的 SteamEdge 版本（設定 → 關於）。
3. 你的 Windows 版本。
4. 記錄檔：設定 → 進階 → 開啟**保留除錯記錄**，重現問題後附上 `cache/steamedge.log`。

**切勿附上 `settings/session.json` 或 `settings/accounts.json`。** 它們含有你的登入權杖。

安全性漏洞請依循 [SECURITY.md](../../SECURITY.md)，不要開立公開 issue。

### 我能幫上什麼忙？

歡迎翻譯、回報問題與提交 Pull Request - 見 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
介面字典位於 `src/main/js/i18n.js`；新增一種語言就是新增一個欄位。
