A scenario check of Realistic Mode and the tray found four defects; they are fixed and every scenario is now a test.

### Fixed

- **A Realistic Mode run that was resumed after a restart was squeezed a second time.** A run with the automatic duration on a game that was already played to its completion time is planned over a few hours. When the app was closed and the run resumed, the "finished game" compression (the setting that shrinks the schedule to a share of the time) was laid on the time that was left: 30 unlocks planned for the last hour ended after 30 minutes. A resumed run now keeps the fact that its duration was the automatic one.
- **Pressing Stop on a Realistic Mode run wrote two lines to the activity feed and sent a "Realistic Mode finished" notification.** The Stop button wrote a line and the engine's confirmation wrote another. The confirmation of a stop that was asked for on the page is no longer written a second time. A run that ends by itself or because the connection went still writes its one line and notification.
- **The tray could lose the window.** The tray click, the tray menu, a second copy of the app and a notification each had their own way to bring the window back, and a window that Windows had minimised (Win+D) could stay minimised. They now share one function that restores and shows it. The minimise button also checks that the tray icon image was found: with a missing image the tray entry would be invisible, so the window is minimised to the taskbar instead of being hidden behind it.
- **The average gap shown while a Realistic Mode run goes** used the whole duration divided by the count, although a finished game ends its unlocks at a share of it; it now uses the placed unlock times, the same as the preview before the start.

### Changed

- `npm test` runs 55 tests. New: `tests/unit/realistic-run.test.js` drives a real run with a fake clock and a fake engine (a clean run, the connection dropping and coming back, the time running out while it was down, the engine gone, a stop with a timer pending and with an unlock in flight, a failed unlock, a queue of games, the queue off, keeping hours, the start and the resume of a finished game); `tests/unit/window-tray.test.js` covers hide, restore, minimised, both, no tray, missing icon and no window; `tests/integration/ui-realistic.test.js` now sends the page a running tick, a stop, a run that ends by itself and a run that dies with the connection, and checks the clock, the buttons, the feed and the notifications.
